## Semantic and axiom audit

- **Anthropic:** `Statement.lean` imports Mathlib and explicitly defines `Computes`, `Approximates`, polynomial families, VP, VNP and the main propositions. `Solution.lean` connects these definitions to `Paper.thm_allfields`, `Paper.thm_approx` and `Paper.cor_allclasses`. The visible `sorry` occurrences are in `Challenge.lean`, whose own comment identifies it as a statement-only Comparator challenge; they are not imported by `Solution.lean`. A repository-wide `rg -n 'sorry|admit|axiom |opaque ' vp-vnp -g '*.lean'` found those `Challenge.lean` `sorry`s and no custom axiom declaration in the checked tree. This is a lexical audit, not a semantic proof of every imported definition. The repository [README](https://github.com/anthropics/formal-math/blob/11b6c7e3c927df2658f513b6b68ea7f8929c62c5/vp-vnp/README.md) explicitly says no human mathematician had checked the proof and no machine checks the intended meaning of `Statement.lean`.
- **OpenAI:** The standalone [`ComparatorChallenges/VPVNP.lean`](https://github.com/openai/math/blob/3344da59991ed94f9ba711217b29c1d760badfa6/lean/ComparatorChallenges/VPVNP.lean) contains a `sorry` in its **challenge statement**, not the actual `ClassSeparation.lean` proof. The actual module imports `Separation.lean` and `Valiant/Project.lean`, whose visible conclusion is exact nonuniform VP≠VNP. A targeted text scan of those three files plus `FamilyResult.lean` and `FixedPaperPairCompiler.lean` found no `sorry`, `admit`, `axiom` or `opaque` declarations. A wider `git grep` of the 3,146-path VPVNP subtree was started but stopped during sparse checkout's large lazy-blob fetch; **no subtree-wide negative scan result is claimed**. The comparator JSON permits only `propext`, `Quot.sound`, `Classical.choice` and sets `enable_nanoda=false`. The large transitive proof library was not independently axiomatized or semantically audited in this round. The repository [README](https://github.com/openai/math/blob/3344da59991ed94f9ba711217b29c1d760badfa6/README.md) calls manuscripts raw research data and warns some unformalized results may have issues.
- **Model consistency checked, limited:** neither top-level statement is trivially vacuous on its face: Anthropic's `Computes` allows lists of gates formed from earlier entries and `VNP` sums a VP verifier over Boolean witnesses; OpenAI's comparator permits reuse of earlier binary gates and free variables/constants. Anthropic counts those inputs as gates, a polynomially equivalent size convention. Neither audit independently proves all reductions from their internal tensor definitions to the customary VP/VNP definitions. The exact-versus-border discrepancy on OpenAI's side is a **scope limit**, not evidence that its exact theorem is false.

## Reproduction log

The source checkouts were placed outside this repository in `%TEMP%/rcp-v8-primary-sources`, with the full commit IDs above. `git ls-remote` and `git rev-parse HEAD` agreed. Anthropic specifies Lean `v4.33.1`, Mathlib commit `0df444a360eaa60ab8c11dca51a86af692955474`; OpenAI pins Lean `v4.34.1` and a much larger integrated Lean library. Commands for a fresh checkout:

```text
git clone --depth 1 --filter=blob:none --sparse https://github.com/anthropics/formal-math.git
cd formal-math
git checkout 11b6c7e3c927df2658f513b6b68ea7f8929c62c5
git sparse-checkout set vp-vnp
cd vp-vnp
lake exe cache get
lake build
lake env lean scripts/PrintAxioms.lean
```

On this Windows host, `lake` was initially absent from `PATH`; commands used `%USERPROFILE%\.elan\bin\lake.exe`. `lake exe cache get` succeeded, downloading/decompressing 8,690 Mathlib cache files. A separate `lake build Statement` succeeded (`8707 jobs`, `Statement` in 231 seconds), checking the *definition and theorem-statement module only*. Two attempts at the full `lake build` failed during parallel compilation around jobs 8,706–8,718 of 9,032: Lean reported inability to read toolchain `Lean/Widget/*.olean`, `.olean.private`, `.ir` and `Lean/Data/Lsp/LanguageFeatures.olean` files. Those paths existed on disk when checked. The retry was stopped after the same class of I/O error recurred. This is a **local Windows build failure**, not a counterexample to the mathematics and not a successful proof reproduction. Consequently `lake env lean scripts/PrintAxioms.lean` could not complete, and no independent external axiom audit is claimed. Anthropic reports successful internal CI and a second-kernel check in its README, which is distinct from our independent attempt.

OpenAI's `lean/` tree has roughly 190,020 tracked paths and a large dependency graph; its own [Lean README](https://github.com/openai/math/blob/3344da59991ed94f9ba711217b29c1d760badfa6/lean/README.md) recommends small builds. The pinned sources and `ClassSeparation`/Comparator top-level statements were inspected, but the full transitive library, pinned dependencies and a targeted build were not reproduced on this host. No independent OpenAI axiom audit is claimed. A focused clean Linux build and semantic review of both formal statements are follow-up verification work, not a prerequisite for the project's model-boundary counterexample.

## Correction and review status

Anthropic's pinned README disclaims human review. OpenAI's pinned history records a 24 November superseding manuscript family, not a retraction of the 23 November claim. The two laboratories' formalizations and internal CI are separate from independent expert validation. Neither source proves a Boolean or quantum circuit lower bound, and both primary papers state that P versus NP is not settled. The project will not elevate these claims to established complexity facts on the basis of a successful Lean build alone.
